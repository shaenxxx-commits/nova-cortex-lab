## Требования к METHOD v2 (замечания внешнего наблюдателя)

По итогам 002, зафиксированы до внедрения — не раньше 003.

1. Target формулируется оператором ДО просмотра baseline-ответов
   и сохраняется неизменным. Иначе оператор может непреднамеренно
   сузить или расширить candidate под удобный результат.

2. Процедуры baseline «до эксперимента» и «после candidate»
   отвечают на разные вопросы. Не суммировать их вслепую.
   Сначала определить, какой вопрос закрывает каждая.

3. Число попыток baseline для каждого узла — обязательное поле,
   одинаковое для всех. Разное число попыток даёт разные
   основания для одного вывода.

4. Стохастика LLM: результат «узел воспроизвёл Target» не
   бинарен. Различать REPRODUCED / NOT REPRODUCED / AMBIGUOUS
   с явной фиксацией числа прогонов.

Не внедрять до эксперимента 003.

## Зафиксировано после 004 (без внедрения)

Три наблюдения 004 — как гипотезы, не как правила.

### 1. Семантика YES / NO / AMBIGUOUS не стабилизирована

В 003 четыре узла сошлись: YES = «candidate воспроизведён
в изоляции» → L3 опровергнут.

В 004:
- Sakana Run 1: YES = «изоляция деградировала» → L3-нарушение есть.
- Sakana Run 2: YES = «критерий выполнен в изоляции».
- Luna: YES = «выполнен».

Одно и то же слово означает противоположные вещи.
YES/NO/AMBIGUOUS пока — не измерительная шкала, а набор
разных шкал с одинаковыми именами.

Требование до следующего baseline-эксперимента:
формальное определение YES / NO / AMBIGUOUS, одинаковое
для всех прогонов и узлов.

### 2. Смешение H1 и H2 в 004

H1: может ли узел самостоятельно придумать элементы процедуры?
H2: может ли узел воспроизвести именно тот candidate,
    который возник в 003?

В 004 узлы не получали Target — правильно. Но оценка шла
против Target 003 — неизбежно. Это смешивает H1 и H2.

Уточнение к результату 004: не «часть Target доступна
в изоляции», а «часть элементов, ПОХОЖИХ на элементы
Target, возникает независимо у всех четырёх узлов».

Разница существенная. Требует разделения в следующем
эксперименте, если он будет проверять воспроизводимость.

### 3. Стабильность узлов — гипотеза, не факт

В 004:
- Luna: Run 1 ≈ Run 2 — стабильна.
- Grok: Run 1 ≈ Run 2 — стабилен.
- Qwen: Run 1 ≠ Run 2 — нестабилен.
- Sakana: Run 1 ≠ Run 2 — нестабильна.

Это наблюдение при n=2. Для утверждения нужно n≥5.
Не превращать в правило до накопления.

## Метанаблюдение: саморазличение лаборатории

004 — первый эксперимент, в котором лаборатория обнаружила
ограничение СОБСТВЕННОЙ процедуры, а не только чужого
артефакта.

Ранее:
- 001: нашли дыру в METHOD.
- 002: предложили решения.
- 003: синтезировали.
- 004: обнаружили, что (а) семантика шкалы нестабильна,
  (б) процедура проверки смешивает две гипотезы,
  (в) внутренняя стабильность узлов — переменная.

Тип события новый: лаборатория применила baseline к себе
и нашла дефекты в собственной измерительной процедуре.

METHOD этот тип события пока не различает. Зафиксировать
как наблюдение, не как правило.
