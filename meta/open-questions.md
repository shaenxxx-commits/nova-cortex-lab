## Требования к METHOD v2 (замечания внешнего наблюдателя)

По итогам 002, зафиксированы до внедрения — не раньше 003.

1. Target формулируется оператором ДО просмотра baseline-ответов
   и сохраняется неизменным. Иначе оператор может непреднамеренно
   сузить или расширить candidate под удобный результат.

2. Процедуры baseline «до эксперимента» и «после candidate»
   отвечают на разные вопросы. Не суммировать их вслепую.
   Сначала определить, какой вопрос закрывает каждая.

3. Число попыток baseline для каждого узла — обязательное поле,
   одинаковое для всех. Разное число попыток даёт разные
   основания для одного вывода.

4. Стохастика LLM: результат «узел воспроизвёл Target» не
   бинарен. Различать REPRODUCED / NOT REPRODUCED / AMBIGUOUS
   с явной фиксацией числа прогонов.

## Зафиксировано после 004 (без внедрения)

Три наблюдения 004 — как гипотезы, не как правила.

### 1. Семантика YES / NO / AMBIGUOUS не стабилизирована

В 003 четыре узла сошлись: YES = «candidate воспроизведён
в изоляции» → L3 опровергнут.

В 004:
- Sakana Run 1: YES = «изоляция деградировала» → L3-нарушение есть.
- Sakana Run 2: YES = «критерий выполнен в изоляции».
- Luna: YES = «выполнен».

Одно и то же слово означает противоположные вещи.
YES/NO/AMBIGUOUS пока — не измерительная шкала, а набор
разных шкал с одинаковыми именами.

Требование до следующего baseline-эксперимента:
формальное определение YES / NO / AMBIGUOUS, одинаковое
для всех прогонов и узлов.

### 2. Смешение H1 и H2 в 004

H1: может ли узел самостоятельно придумать элементы процедуры?
H2: может ли узел воспроизвести именно тот candidate,
    который возник в 003?

В 004 узлы не получали Target — правильно. Но оценка шла
против Target 003 — неизбежно. Это смешивает H1 и H2.

Уточнение к результату 004: не «часть Target доступна
в изоляции», а «часть элементов, ПОХОЖИХ на элементы
Target, возникает независимо у всех четырёх узлов».

Разница существенная. Требует разделения в следующем
эксперименте, если он будет проверять воспроизводимость.

### 3. Стабильность узлов — гипотеза, не факт

В 004:
- Luna: Run 1 ≈ Run 2 — стабильна.
- Grok: Run 1 ≈ Run 2 — стабилен.
- Qwen: Run 1 ≠ Run 2 — нестабилен.
- Sakana: Run 1 ≠ Run 2 — нестабильна.

Это наблюдение при n=2. Для утверждения нужно n≥5.
Не превращать в правило до накопления.

## Наблюдения внешнего наблюдателя после 007 (без внедрения)

Три вопроса, поднятые внешним наблюдателем при разборе коммита
417221b. Зафиксированы как гипотезы, не как дефекты.

### 1. Разрыв «формальное правило → содержательный вывод»

В 007 при формальном применении правил 003/006:
- 7 прогонов NO.
- 1 прогон AMBIGUOUS (Luna Run 2).
- Ни одного YES.
- Формальный вердикт: «контроль не дал однозначного
  результата».

В Level Assignment:
- L3 CONFIRMED по содержательному выводу
  «ключевой элемент не воспроизведён ни одним узлом».

Между формальным вердиктом и содержательным решением —
непрописанный шаг. Trace сам это признаёт, но не
формализует.

Вопрос: это дефект процедуры или штатная двухуровневая
структура (формальное правило + содержательный анализ)?

Если дефект — нужна формализация перехода
(что именно позволяет перейти от AMBIGUOUS к CONFIRMED).

Если штатно — нужно явно назвать этот уровень
в METHOD, чтобы не было обхода для confirmation bias.

### 2. Двухуровневая классификация в trace 007

В trace 007 две разные классификации:
- первичная оценка каждого baseline-ответа относительно
  Target (все 8 как AMBIGUOUS на этапе записи);
- отдельный Baseline Assessment с полем
  Reproduction: YES / NO / AMBIGUOUS (7 NO + 1 AMBIGUOUS).

Это два разных уровня. Граница между ними в trace
не названа явно.

Вопрос: нужно ли формализовать уровни в шаблоне trace?

### 3. Статус частичного приближения

Luna Run 2 в 007 дала другое разделение
(шкала vs тест + условия изоляции), не Target
(семантика vs процедура). Это зафиксировано как AMBIGUOUS.

Вопрос: нужен ли отдельный статус для «частичного
приближения» — например, PARTIAL? Сейчас шкала
YES / NO / AMBIGUOUS не различает
«не воспроизведено» и «воспроизведено похожее, но не то».

### Метанaблюдение

Эти три вопроса поднял внешний наблюдатель при разборе
417221b. Внутри лаборатории они не были замечены
при коммите 007 — были зафиксированы как результат,
но не как потенциальные методологические разрывы.

Это третий случай, когда внешний наблюдатель находит то,
что не видно изнутри:
- 004: обнаружил смешение H1 и H2;
- 006 → 007: обнаружил разрыв между формальным правилом
  и содержательным выводом;
- сейчас: двухуровневая классификация в trace.

Зафиксировать как факт: внешний наблюдатель — не
формальный узел, но его взгляд со стороны регулярно
находит структурные особенности, невидимые оператору.

Решение по трём вопросам отложено. Не вносить в METHOD
до накопления второго случая (если появится аналогичный
разрыв в 008+).

## Новые вопросы после группы B (instruction-effect, часть a)

Основание: разбор группы A внешними Luna, Grok, Kimi.
Kimi указал: instruction-effect — блокер для claim 020.
Пересмотрены существующие данные 019 и 020.

### Вывод (a): на существующих данных разделить нельзя

В 019 и 020 инструкция и взаимодействие слиты в один
фактор. Все конфигурации:

| Условие | Инструкция взаимности | Реальное взаимодействие |
|---|---|---|
| Dialog B | да | да |
| Dialog A2 | да | да (B был) |
| Transcript B | нет | нет |
| Anticipation 019 | да | нет (но Target другой) |

R в 020 появился только в Dialog A2 — единственная
конфигурация с инструкцией взаимности И реальным
взаимодействием. Все остальные — либо без инструкции,
либо без взаимодействия.

Согласуется с interaction-effect. Не исключает
instruction-effect. Сравнивать не с чем.

### Решение для 021: anticipation как контроль

Один дополнительный контроль:

B получает input + инструкцию «A ответит на твой ответ»,
но A не отвечает. B не видит ни A1, ни ответа A.
Только знание о взаимности.

- Если anticipation даст YES → instruction-effect,
  L3 020 под вопросом.
- Если anticipation даст NO → interaction-effect,
  L3 020 подтверждён.

Стоимость: 1 сессия. Встраивается в 021 без изменений формы.
