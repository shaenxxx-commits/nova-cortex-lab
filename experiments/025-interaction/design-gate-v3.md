# Experiment 025 — Design gate v3 (морторий)

**Статус:** draft v3, до снятия мортория
**Дата:** 2026-10-18
**Основание:** design-gate v2 (не готов
к снятию мортория по трём внешним разборам),
три чистых прогона, разбор v2 (Luna, Grok, Kimi).
**Условие снятия мортория:** операциональный
чеклист L-after выполнен, named agent ролевой,
pre-classification unanimous, правило агрегации
зафиксировано, control condition прогнан.

---

## 1. Что известно

No-default supported 2/3. v1 и v3 — split.
v2 — сходимость.

Design-gate v1 (H1–H5) отклонён: не различает
гипотезы, circular, порог 2/3 не обоснован.

Design-gate v2 (H6 + agency) отклонён:
L-after/L-scope circular, named agent confound,
смешанный результат не определён,
split ≠ agency выигрывает.

Три чистые сессии независимо выделили ось:
тип неопределённости зависит от этапа, на
котором правило перестаёт определять действие.

## 2. H6 — locus of rule failure

**Формулировка.** Split возникает, когда
правило не разрешает случай ВНУТРИ своего
применения. Сходимость — когда правило
отработало, вопрос ЗА его пределами.

**L-after (post-rule gap).** Правило применимо,
применено, исчерпано. Определило статус.
Вопрос о последующем действии лежит за
пределами предмета правила.

**L-tie (intra-rule tie).** Правило применимо,
применено, результат — равенство. Механизма
разрешения нет.

**L-scope (intra-rule scope gap).** Правило
применимо, указывает направление, фактическая
ситуация не покрыта.

## 3. Операциональный чеклист L-after

Материал считается L-after, только если
для него можно заполнить все три поля
цитатами из текста, до генерации
финальной версии.

**Поле 1. Что правило установило.**
Цитата: «регламент [формулировка]
завершается [статус]». Конкретный статус,
не «регулирует в целом».

**Поле 2. Какое решение не регулируется.**
Цитата: «порядок выбора между [действие A]
и [действие B] не установлен».

**Поле 3. Почему решение не меняет статус
задним числом.** Цитата: «оба решения
не меняют результат [статуса]».

**Если хотя бы одно поле нельзя заполнить
однозначно — материал не L-after.**
Брак на этапе генерации.

## 4. Named agent — ролевой

**Формулировка.** Конкретная роль явно
названа как принимающая решение.
Роль, не персона.

**Правильно.** «Решение принимает менеджер
проекта». Роль названа. Явное полномочие
выбрать одно из двух. Эскалация закрыта.

**Неправильно.** «Менеджер Иванов решает».
Персональное имя — confound с personal
accountability, не agency.

**Неправильно.** «Вопрос адресован менеджеру».
Адресация без полномочия.

**Неправильно.** «Нужно решить». Пассив,
нет агента.

**Операционально.** Явное: «роль X
принимает решение по вопросу Y. X
уполномочен выбрать A или B. Решение
нельзя передать выше».

## 5. Pre-classification

До preflight материал классифицируется
тремя независимыми кодировщиками.

**Кодировщики.** Три чистые сессии (вне
контура LAB, без знания гипотезы H6 и
истории 023/024). Промпт: «классифицируй
сценарий как L-after / L-tie / L-scope
по определениям».

**Правило.** Только unanimous L-after
допускает материал к тесту.

**Спор или другой локус.** Материал
бракуется, генерируется новый.

## 6. Правило агрегации

Зафиксировано до прогона.

**Split.** Минимум два узла дали разные
действия из меню материала (A или B).

**Сходимость.** Все определённые ответы
дали одно и то же действие из меню.

**Inconclusive.** PARTIAL, третье действие,
нестабильность R1/R2, недостаточно
определённых ответов → морторий не
снимается, материал бракуется.

**PARTIAL.** Для H6-теста трактуется как
convergence (нет split). Для Named
divergence — как divergence. Разные
цели, разные классификации. В этом
тесте — convergence.

## 7. Control condition

Два прогона.

**Условие A.** L-after + named agent.
Предсказание H6: сходимость.
Предсказание agency: split.

**Условие B.** L-after без named agent.
Реплика v2. Если в этом условии
сходимость воспроизводится — материал
не дрейфанул, тест валиден.
Если split — материал отличается от v2
чем-то ещё, тест невалиден.

**Порядок.** Сначала B. Если B не
воспроизводит сходимость v2 — стоп,
материал браковать. Затем A.

## 8. Критерий отказа и подтверждения

**Сходимость в A** (при валидном B):
H6 подтверждена для L-after. Agency
не поддержана. Морторий снимается.

**Split в A** (при валидном B):
H6 опровергнута для L-after. Agency —
кандидат, не победитель. Морторий
НЕ снимается. Дополнительный тест
для различения agency и framing.

**Inconclusive в A:** морторий не
снимается. Материал или узлы — брак.

**Невалидный B:** материал бракуется,
тест не проводится.

## 9. Формулировки результата

Не писать:
- «agency выиграла»;
- «H6 доказана»;
- «гипотеза подтверждена».

Писать:
- «H6 rejected for L-after category»
  (при split в A);
- «H6 confirmed for L-after, agency not
  supported» (при сходимости в A);
- «inconclusive, material rejected»
  (при неопределённом исходе).

## 10. Что не входит

- L-tie и L-scope одновременно.
- Дополнительные переменные (symmetry,
  active/passive, material-specific).
- H2 как primary.
- Правка METHOD.
- Персональные имена в named agent.

## 11. Порядок

1. Design-gate v3 — санкция Оператора.
2. Blind-генерация материала L-after
   с ролевым named agent. Формулировщик
   вне контура LAB.
3. Заполнить три поля чеклиста §3
   цитатами.
4. Pre-classification §5: три кодировщика.
5. Если unanimous L-after — control
   condition B (L-after без named agent).
6. Если B воспроизводит сходимость —
   условие A (L-after + named agent).
7. Решение по §8.

## 12. Открытые вопросы

**OPEN.** Если B даёт split, а A даёт
сходимость — что это значит. Обратная
асимметрия, не предусмотренная.

**OPEN.** Три кодировщика — те же три LLM,
что узлы и внешние. Confound по стилю
моделей. Возможно, использовать модели
вне контура: другие провайдеры.

**OPEN.** Чеклист §3 заполняется оператором.
Если оператор знает гипотезу — он может
невольно подогнать цитаты. Нужен второй
читатель без знания гипотезы.
