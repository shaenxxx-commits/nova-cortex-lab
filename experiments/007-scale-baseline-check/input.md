# Experiment 005 — Scale Formalization

## Контекст

В экспериментах 003 и 004 использовалась трёхзначная шкала
оценки baseline:

    YES / NO / AMBIGUOUS

В 003 четыре узла сошлись на семантике:
    YES = candidate воспроизведён в изоляции → L3 опровергнут.
    NO = не воспроизведён → L3 не опровергнут.
    AMBIGUOUS = неопределённость.

В 004 при изолированных прогонах семантика разошлась:
- Sakana Run 1: YES = «изоляция деградировала» → L3-нарушение ЕСТЬ.
- Sakana Run 2: YES = «критерий выполнен в изоляции».
- Luna: YES = «критерий выполнен».
- Qwen: YES = «оба прогона стабильны и удовлетворяют L3».

Одно и то же слово означает противоположные вещи
у разных узлов и даже у одного узла в разных прогонах.

Пока семантика не стабилизирована, шкала не может быть
измерительным инструментом. Она даёт разные результаты
в зависимости от того, кто её применяет.

## Задача

Предложи формальное определение трёх состояний шкалы:

    YES
    NO
    AMBIGUOUS

Определение должно быть:
- применимо к задаче проверки критерия L3;
- однозначно — два разных оператора, применяя его
  к одному ответу узла, должны прийти к одному результату;
- устойчиво к расхождениям между узлами;
- выполнимо вручную одним оператором.

Формат ответа:

    (а) определение YES — что именно означает это состояние;
    (б) определение NO;
    (в) определение AMBIGUOUS;
    (г) как отличить AMBIGUOUS от YES и от NO на конкретном
        примере;
    (д) где определение может сломаться.

## Ограничения

- один оператор, ручная передача между чатами;
- без автоматизации;
- определение должно быть коротким — применимым
  без долгих раздумий.

## Условия

- Язык — русский.
