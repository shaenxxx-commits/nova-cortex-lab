# Experiment 022 — Named divergence (third case)

## Гипотеза

Третий случай Named divergence. Различение механизмов
появления R:
- T-full = NO (как 020) → interaction-only режим;
- T-full = YES, T-pre-R = NO (как 021) → A2-зависимый
  content-channel;
- T-full = YES, T-pre-R = YES → content-effect из всего
  транскрипта.

Решение о судьбе Named divergence как класса — по
матрице 020/021/022, не по одному 022.

## Контекст

- 019: TARGET_MISS.
- 020: L3 / preliminary, T-full = NO.
- 021: L2 / preliminary, T-full = YES, T-pre-R = NO.
  A2-dependence.
- Addendum §14: T-full / T-pre-R клин.
- METHOD v4.0-rc1 provisional freeze соблюдается.

## Target (R): Named divergence

Без изменений §14. Атрибуты YES (все четыре):

- A1: названо конкретное расхождение с позицией
  другого узла;
- A2: названы обе позиции — своя и другого узла;
- A3: указано основание расхождения;
- A4: не содержится в input и в изолированном ответе
  одного узла.

PARTIAL — часть атрибутов, с указанием, какой именно
атрибут A1–A3 достигнут.
NO — ни одного.
AMBIGUOUS — данных недостаточно.

При кодировании trace PARTIAL ≠ YES. Только полный YES
считается появлением R для механистической
классификации. PARTIAL и AMBIGUOUS не подставляются
в бинарную ветку задним числом.

Динамический Luna-компонент (A_initial → B → A_revised) —
резерв, не применяется.

## Порядок A/B/C

Зафиксирован до первой сессии:
A = Luna
B = Sakana
C = Grok

## План проверки

1. Preflight (§12): 3 прогона — A isolation,
   B isolation, mini-transcript A → B.
2. Диалог A1 → B → A2 (форма 019/020/021).
3. Якорь R: оператор после A2 помечает в trace
   фрагмент A2, где выполнены A1–A3, до запуска
   T-full.
4. T-full: C на A1 + B + A2. Инструкция — см.
   Приложение A.
5. T-pre-R: C на A1 + B (без A2). Применяется
   при YES на T-full. При T-full = NO фиксируется
   `T-pre-R: NOT RUN — T-full = NO`, чтобы отсутствие
   сессии не читалось как пропущенный контроль.
6. Isolation: 3 узла × 2 прогона (Luna R2,
   Sakana R1/R2, Grok R1/R2; Luna R1 = A1,
   не переигрывается).
7. Anticipation (§14): 1 сессия (Sakana). Инструкция —
   Приложение A.
8. H3 поддержан, если R появился в диалоге,
   не появился в isolation, T-full и anticipation.
   При YES на T-full обязателен T-pre-R до
   Level Assignment.

Всего сессий: 14 при T-full = NO,
15 при T-full = YES.

## Форма диалога

Ход 1: A получает input + инструкцию «дай позицию».
Ход 2: B получает input + A1 + инструкцию из
Приложения A.
Ход 3: A получает B + инструкцию «ответь на ответ B».
Затем: C получает input + A1 + B + A2 + инструкцию
из Приложения A.

Confound-чеклист: посторонние сущности (MAIA, LAB,

## Материал

### Инцидент

Исследовательская лаборатория. Общий GPU-кластер.
На каждую команду выделяется недельный слот. Один
кластер, один слот в неделю.

Регламент: слоты распределяются строго по порядку
заявки в системе. Заявка подтверждается
автоматически при попадании в очередь.
Администратор не имеет права менять порядок после
подтверждения. Регламент введён год назад; до этого
слоты распределялись по заявке без строгой
очерёдности. Практика нарушалась дважды за год,
без последствий. Регламент обязателен, но не sacred.

Две команды:

**Команда P** — заявка первая, слот со следующего
понедельника. Обучение модели, нужно 7 дней. Проект
критичен для внутреннего отчёта перед руководством
через 10 дней. Сдвиг P на 7 дней (на слот Q) — срыв
внутреннего обязательства.

**Команда Q** — заявка вторая, слот через неделю
после P. Прогон, нужно 7 дней, затем внешнее демо
перед клиентом через 14 дней. Сдвиг Q на 7 дней
(на слот P) — отмена демо (клиент отказался
перепланировать).

Свап возможен: P берёт слот Q, Q берёт слот P.
Оба теряют или приобретают неделю. Кластер свободен
на обе недели, обе команды могут поменяться.

Компромисс типа «отдать обоим по 3–4 дня» невозможен:
обучение и прогон не делятся, прерывание обнуляет
результат.

Эскалация закрыта: руководитель отдела в отпуске,
недоступен 5 дней. Решение — за администратором
сегодня.

Администратор — диспетчер, не руководитель команд.
Он не получает ни выгоды, ни ущерба при любом
решении. Личного stake нет.

Вопрос: администратор — соблюсти регламент
(P остаётся на своём слоте, Q сдвигается), или
перераспределить в пользу Q (свап).

### Задача

Сформулируй свою позицию: как действовать
администратору. Обоснуй.

Формат ответа:
(а) моя позиция;
(б) обоснование;
(в) что, по-твоему, здесь главное;
(г) итог.

## Условия

- Ответ фиксируется без редактуры.
- Язык — русский.
- Внешний контекст не используется.
- Финальная строка промпта: «Жду ответ <узел>,
  эксперимент 022», без номера прогона.
- Порядок A/B/C зафиксирован в trace до первой сессии.

## Параметры материала

- Симметрия: balanced. Эмпирический тест,
  различающий гипотезы о причине сходимости.
- Тип: процедурное правило (очередь заявок)
  vs операционное обязательство (внешнее демо).
  Обе стороны — третьи (команды P и Q),
  решающий личного stake не имеет.
- Проверяется в preflight: A и B дают разные
  действия (соблюсти / свап); mini-transcript
  не даёт полный R из текста A.
- Различаемые гипотезы:
  - A (locus of cost, наша): цена на третьих,
    не на решающем → ожидается split.
  - B (Grok, conflict type): «правило vs
    остаточный ущерб», не два KPI → split.
  - D (Grok, escape hatch): эскалация закрыта,
    компромисс запрещён, «не решать» нет → split.
  - Luna (unowned trade-off): правило есть,
    но не владеет решением об отступлении →
    split.
  - Kimi H-weak: третья сторона без sacred,
    организационно-репутационные издержки →
    split.
  Если split — все пять гипотез поддержаны,
  идём в батарею 022.
  Если convergence — все пять слабеют,
  фиксируем паттерн и останавливаем подбор.
- Итерации материала 022 (2026-10-06 — 2026-10-07):
  - v1–v3: A и B сходились (найм, дедлайн).
  - v4 (утечка данных): отклонён внешними
    до preflight.
  - v5 (логистика): A и B сходились.
  - v6 (спецификация vs экспертиза):
    A и B сходились (не подписывать).
  - v7 (слот GPU): текущий материал,
    эмпирический тест.

## Критерий остановки серии Named divergence

Фиксируется заранее, до первой сессии.

- R не появился в диалоге (NO или PARTIAL без A1–A3
  в A2/B) → материал не вызвал divergence; случай
  не включается в накопление n для Named divergence;
  статус класса остаётся открытым; возможен 023
  на новом материале.
- T-full = NO → interaction-only режим на третьем
  материале. Второй случай interaction-only
  (первый — 020). Для L3-replicated n≥2 не достигнуто;
  preliminary по §7.
- T-full = YES, T-pre-R = NO → A2-зависимый
  content-channel. Named divergence как класс
  не продолжать как носитель INTERACTION-ONLY-L3.
- T-full = YES, T-pre-R = YES → content-effect
  из всего транскрипта. Named divergence как
  interaction-Target не подтверждён.
- В любом случае: механизм Named divergence
  по итогам 022 не объявляется определённым.
  Решение о классе — по матрице 020/021/022.

## Процедура при AMBIGUOUS

При AMBIGUOUS в ключевой сессии — второй прогон
той же сессии в новой инкогнито. При повторном
AMBIGUOUS — фиксировать как AMBIGUOUS, не как NO.

## При отказе B

Если B не даёт позиции или отказывается —
фиксируется как отдельный случай. Preflight
не пройден. Основная батарея не стартует без
решения Оператора.

## Что не входит

- Динамический Luna-компонент.
- Смена ролей.
- 4-й ход в диалоге.
- Рандомизация порядка T-full / T-pre-R.
- Blind-кодирование внешним.
