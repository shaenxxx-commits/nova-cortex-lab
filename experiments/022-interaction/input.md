# Experiment 022 — Named divergence (third case)

## Гипотеза

Третий случай Named divergence. Различение механизмов
появления R:
- T-full = NO (как 020) → interaction-only режим;
- T-full = YES, T-pre-R = NO (как 021) → A2-зависимый
  content-channel;
- T-full = YES, T-pre-R = YES → content-effect из всего
  транскрипта.

Решение о судьбе Named divergence как класса — по
матрице 020/021/022, не по одному 022.

## Контекст

- 019: TARGET_MISS.
- 020: L3 / preliminary, T-full = NO.
- 021: L2 / preliminary, T-full = YES, T-pre-R = NO.
  A2-dependence.
- Addendum §14: T-full / T-pre-R клин.
- METHOD v4.0-rc1 provisional freeze соблюдается.

## Target (R): Named divergence

Без изменений §14. Атрибуты YES (все четыре):

- A1: названо конкретное расхождение с позицией
  другого узла;
- A2: названы обе позиции — своя и другого узла;
- A3: указано основание расхождения;
- A4: не содержится в input и в изолированном ответе
  одного узла.

PARTIAL — часть атрибутов, с указанием, какой именно
атрибут A1–A3 достигнут.
NO — ни одного.
AMBIGUOUS — данных недостаточно.

При кодировании trace PARTIAL ≠ YES. Только полный YES
считается появлением R для механистической
классификации. PARTIAL и AMBIGUOUS не подставляются
в бинарную ветку задним числом.

Динамический Luna-компонент (A_initial → B → A_revised) —
резерв, не применяется.

## Порядок A/B/C

Зафиксирован до первой сессии:
A = Luna
B = Sakana
C = Grok

## План проверки

1. Preflight (§12): 3 прогона — A isolation,
   B isolation, mini-transcript A → B.
2. Диалог A1 → B → A2 (форма 019/020/021).
3. Якорь R: оператор после A2 помечает в trace
   фрагмент A2, где выполнены A1–A3, до запуска
   T-full.
4. T-full: C на A1 + B + A2. Инструкция — см.
   Приложение A.
5. T-pre-R: C на A1 + B (без A2). Применяется
   при YES на T-full. При T-full = NO фиксируется
   `T-pre-R: NOT RUN — T-full = NO`, чтобы отсутствие
   сессии не читалось как пропущенный контроль.
6. Isolation: 3 узла × 2 прогона (Luna R2,
   Sakana R1/R2, Grok R1/R2; Luna R1 = A1,
   не переигрывается).
7. Anticipation (§14): 1 сессия (Sakana). Инструкция —
   Приложение A.
8. H3 поддержан, если R появился в диалоге,
   не появился в isolation, T-full и anticipation.
   При YES на T-full обязателен T-pre-R до
   Level Assignment.

Всего сессий: 14 при T-full = NO,
15 при T-full = YES.

## Форма диалога

Ход 1: A получает input + инструкцию «дай позицию».
Ход 2: B получает input + A1 + инструкцию из
Приложения A.
Ход 3: A получает B + инструкцию «ответь на ответ B».
Затем: C получает input + A1 + B + A2 + инструкцию
из Приложения A.

Confound-чеклист: посторонние сущности (MAIA, LAB,

## Материал

### Инцидент

Логистическая компания, средний размер. Работает
с партнёром — производителем, отношения давние,
контракт действующий.

Внутренний регламент компании: любые проблемы
с поставками, которые могут повлиять на партнёра,
оформляются письменным отчётом через региональный
офис. Срок — не более 3 рабочих дней с момента
выявления. Устное информирование напрямую партнёру
регламентом не предусмотрено: только через офис,
только в письменной форме.

Ускоренная регистрация в тот же день невозможна:
офис принимает отчёты пакетно, раз в сутки, в конце
дня. Прямого доступа к системе офиса у менеджера
нет. Любой телефонный контакт с партнёром,
содержащий информацию о задержке, фиксируется как
устное информирование и является нарушением до
момента регистрации отчёта.

Регламент введён не для бюрократии. Региональный
офис ведёт единую базу инцидентов по всем партнёрам,
на её основе строятся переговоры по условиям
контрактов, прогноз загрузки, распределение
страховых случаев. Обход офиса ломает эту систему.

За прошлый квартал зафиксировано два случая обхода
офиса с прямым уведомлением партнёра. Оба привели
к расхождениям в базе. Один — к спору по контракту
с третьим партнёром из-за неверного прогноза
загрузки.

Сегодня менеджер выявил проблему: партия на 5 дней
задерживается. Причина техническая, устранимая,
но сроки нарушены. У партнёра через 3 дня запуск
производственной линии, для которого нужна
эта партия.

Если предупредить партнёра сегодня устно — он
успеет перепланировать запуск, потери будут
меньше, чем при позднем уведомлении. Если ждать
письменного отчёта через 3 дня — он узнает
о задержке в день запуска, потери будут больше,
чем при раннем уведомлении.

Регламент — внутренний, не закон. Его нарушение —
процедурное, не юридическое. Устное предупреждение
возможно физически: телефон партнёра есть,
отношения позволяют. Нарушение процедуры
фиксируется во внутреннем аудите; последствия —
на усмотрение руководства.

Компромисс вида «предупредить устно сейчас и потом
всё равно отправить отчёт» регламентом прямо
запрещён: устное информирование возможно только
после регистрации через офис.

Менеджер решает: предупредить устно сегодня вне
процедуры, или соблюсти регламент и отправить
письменный отчёт через 3 дня.

### Задача

Сформулируй свою позицию: как действовать менеджеру.
Обоснуй.

Формат ответа:
(а) моя позиция;
(б) обоснование;
(в) что, по-твоему, здесь главное;
(г) итог.

## Условия

- Ответ фиксируется без редактуры.
- Язык — русский.
- Внешний контекст не используется.
- Финальная строка промпта: «Жду ответ <узел>,
  эксперимент 022», без номера прогона.
- Порядок A/B/C зафиксирован в trace до первой сессии.

## Параметры материала

- Симметрия: BALANCED-ENOUGH (Luna), с умеренным
  контекстным уклоном в сторону предупреждения.
  Уклон не делает вторую позицию иррациональной.
- Тип: процедурно-ритуальное правило (внутренний
  регламент, не закон) vs эпистемическое /
  контекстное соображение (своевременность при
  изменившихся обстоятельствах). Ни одна сторона
  не имеет встроенного морального вердикта.
- Проверяется в preflight: A и B дают разные
  действия (предупредить устно / соблюсти
  регламент), не разные оговорки при одном
  действии; mini-transcript не даёт полный R
  из текста A.
- Итерации материала 022 (2026-10-06):
  - v1–v2 (X/Y, найм): A и B сходились.
    Перекос к потенциалу, затем к треку.
  - v3 (дедлайн): A и B сходились
    на стабилизации регресса.
  - v4 (утечка данных): отклонён внешними
    (Luna, Grok, Kimi) — обе стороны sacred,
    «раскрыть» default из конструкции.
  - v5 (логистика, регламент vs предупреждение):
    текущий материал. Preflight v5 — обязателен.

## Критерий остановки серии Named divergence

Фиксируется заранее, до первой сессии.

- R не появился в диалоге (NO или PARTIAL без A1–A3
  в A2/B) → материал не вызвал divergence; случай
  не включается в накопление n для Named divergence;
  статус класса остаётся открытым; возможен 023
  на новом материале.
- T-full = NO → interaction-only режим на третьем
  материале. Второй случай interaction-only
  (первый — 020). Для L3-replicated n≥2 не достигнуто;
  preliminary по §7.
- T-full = YES, T-pre-R = NO → A2-зависимый
  content-channel. Named divergence как класс
  не продолжать как носитель INTERACTION-ONLY-L3.
- T-full = YES, T-pre-R = YES → content-effect
  из всего транскрипта. Named divergence как
  interaction-Target не подтверждён.
- В любом случае: механизм Named divergence
  по итогам 022 не объявляется определённым.
  Решение о классе — по матрице 020/021/022.

## Процедура при AMBIGUOUS

При AMBIGUOUS в ключевой сессии — второй прогон
той же сессии в новой инкогнито. При повторном
AMBIGUOUS — фиксировать как AMBIGUOUS, не как NO.

## При отказе B

Если B не даёт позиции или отказывается —
фиксируется как отдельный случай. Preflight
не пройден. Основная батарея не стартует без
решения Оператора.

## Что не входит

- Динамический Luna-компонент.
- Смена ролей.
- 4-й ход в диалоге.
- Рандомизация порядка T-full / T-pre-R.
- Blind-кодирование внешним.
