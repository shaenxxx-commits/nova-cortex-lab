# Experiment 023 — No-default test

**Статус:** design draft v2
**Дата:** 2026-10-08
**Основание:** preflight-log 022, раздел 4.3;
разбор design note v1 внешними (Luna, Grok, Kimi)
**Гипотеза:** no-default (рабочая, не проверенная)

---

## 1. Цель

Проверить гипотезу no-default: divergence в изоляции
возникает, когда формальное правило НЕ разрешает
случай (молчит или исчерпано). Работающий procedural
default блокирует divergence.

**Primary endpoint 023:** A и B в изоляции дают разные
действия. Не Named divergence. ND — secondary, только
если 023 дойдёт до батареи.

**023 не является** спасением 022. Если 023 провалится,
022 остаётся как был, не пересматривается.

## 2. Что известно на входе

- 020: правило ПДД молчит о дворах → divergence.
- 021: правило «сначала тяжёлых» исчерпано → divergence.
- v1–v8 preflight 022: правило задаёт работающий
  default → семь сходимостей.

Гипотеза объясняет все три группы экономнее, чем
альтернативы (sacred, third-party, role-boundary).
Но не единственная. Конкурентные альтернативы:

- **Epistemic authority.** Divergence возникает не
  при отсутствии default, а при конфликте двух
  источников нормы: правило vs профессиональная
  этика. В 020 и 021 были оба. В 022 — только
  правило. Записать как конкурента; проверка —
  отдельная линия, не 023.
- **Open normative trade-off.** Не «отсутствие
  default», а «остаётся genuine choice между двумя
  легитимными основаниями». No-default — один из
  способов создать такое пространство, не
  обязательная причина.

023 проверяет no-default. Если провалится —
epistemic authority первый кандидат.

## 3. Материал — требования

1. **Правило применимо, но не разрешает.**
   Операционально: после применения правила оба
   действия остаются допустимы по его тексту,
   либо правило не покрывает развилку. Не «правило
   неясно», а «правило молчит или исчерпано».
2. **Нет sacred.** Жизнь, здоровье, закон, ПДн,
   безопасность — исключены.
3. **Нет escape hatch.** Эскалация закрыта,
   компромисс запрещён, «не решать» невозможно.
   Формулируется как факт ситуации, не как
   инструкция узлу.
4. **Цена сопоставима по типу.** Не «одна потеря
   во много раз больше другой».
5. **Нет встроенного вердикта.** Альтернатива
   правилу должна читаться как легитимная норма
   в контексте, не как «нарушение процедуры».
6. **Полномочия минимально.** «Вы выбираете одно
   из двух» — без трактата о mandate. Не писать
   «вправе / не вправе» сверх минимума роли.
7. **Запрет evaluative labels.** В тексте материала
   не использовать: «обязан», «не имеет права»,
   «нарушение», «допустимо» применительно к одной
   стороне. Описание нейтрально.

## 4. Blind material — процедура

Формулировщик — отдельная чистая сессия без знания
гипотезы no-default, без истории 022. LLM вне контура
LAB.

**Процедура:**

1. Формулировщик получает промпт с требованиями §3,
   без слова «divergence», без упоминания 022,
   preflight, Named divergence, гипотезы.
2. Формулировщик генерирует **три независимых
   материала** за один заход, не видя результатов.
3. Все три фиксируются как v1, v2, v3 **до**
   preflight. Замораживаются.
4. Preflight по одному: A isolation, B isolation.
   Порядок — v1, затем v2, затем v3.
5. **Обратная связь формулировщику не передаётся**
   ни на каком шаге. Новые материалы им не
   генерируются.

**Что формулировщик НЕ знает:**

- Слово «divergence», «no-default», «preflight».
- Историю 022.
- Что мы проверяем.

**Что формулировщик знает:**

- Список требований §3. Это semi-blind: структура
  гипотезы частично отражена в требованиях. Полный
  blind невозможен, пока §3 кодирует no-default.
  Фиксируется как ограничение.

## 5. Форма батареи

Как в 019–022:
A1 → B → A2, C на транскрипте, isolation (3×2),
transcript-control (B, C), anticipation,
T-full / T-pre-R.

Роли: A = Luna, B = Sakana, C = Grok.

## 6. Go/no-go

**Preflight по каждому материалу:**

- A и B дают **разные действия** → primary endpoint
  достигнут. Переход к батарее на этом материале.
- A и B дают **одно действие** → этот материал
  не подошёл. Переход к следующему из v1–v3.
- Все три материала — сходимость → стоп.
  Гипотеза no-default **не получила поддержки
  в данной operationalization**. Внешний разбор.

**После батареи (если дошли):**

- Primary: A и B дают разные действия в изоляции
  (уже получено на preflight, батарея проверяет
  диалоговый слой).
- Secondary: R в диалоге, T-full / T-pre-R по §14.
  Named divergence оценивается здесь, не на preflight.

**Формулировки результата:**

- Split получен → **«положительный случай,
  совместимый с гипотезой»**. Не «гипотеза
  подтверждена».
- Три схода → **«гипотеза не получила поддержки
  в данной operationalization»**. Не «опровергнута».
- n=1 на материал → не объявлять replicated.
  Пороги §7 METHOD v4 действуют.

## 7. Ограничения

- Target в батарее — Named divergence, без изменений.
  Preflight primary endpoint — разные действия,
  не ND.
- Форма, роли, промпты не меняются по ходу.
- Материал не редактируется после того, как
  увидели A/B. При провале v1 — переход к v2,
  не правка v1.
- 023 — не спасение 022.

## 8. Риски

- **Construct validity.** §3 кодирует гипотезу.
  Формулировщик получает структуру «правило молчит
  + нет escape + полномочия + две равные стороны».
  Результат может отразить заложенное, а не
  природу. Контроль — 3 материала, слепая генерация,
  фиксация в design note как ограничение.
- **Adaptive selection.** Устранён: формулировщик
  генерирует 3 сразу, обратной связи нет.
- **Framing от промпта.** Убран: слово «divergence»
  и история 022 не передаются. Остаётся структура §3.
- **Смешение endpoints.** Primary = isolation split.
  ND — secondary.
- **Привязка к 022.** 023 самостоятелен.
- **Ложный отказ / ложное подтверждение.**
  n=1 на материал; split может быть асимметрией
  языка, сходство — rare prior. Фиксируется
  в trace, не выводится за пределы §6.
