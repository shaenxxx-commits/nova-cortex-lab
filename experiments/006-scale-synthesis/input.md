# Experiment 006 — Scale Synthesis

## Контекст

Эксперимент 004 показал: семантика шкалы YES / NO / AMBIGUOUS
не стабилизирована. Одно и то же слово означает разные вещи
у разных узлов и даже у одного узла в разных прогонах.

Эксперимент 005 поставил задачу формализации. Четыре узла
предложили четыре принципиально разных определения шкалы:

- Qwen: шкала через одну бинарную фразу-маркер в тексте
  ответа; либо через артефакт, а не интерпретацию;
  либо через явную фиксацию соответствия / деградации /
  отсутствия оценки.

- Sakana: шкала через заранее зафиксированные критические
  атрибуты candidate (≤5), все должны присутствовать для YES.
  В Run 2 базовый объект измерения сменился на пару
  последовательных прогонов.

- Luna: шкала определяется не семантикой слов YES/NO,
  а внешним отношением между наблюдаемым ответом
  и критерием L3. Слово YES само по себе не доказательство.

- Grok: шкала через существенные признаки L3 плюс явный
  вердикт по L3 в определении (YES → L3 опровергнут,
  NO → L3 не опровергнут).

Стабильность узлов: Luna и Grok дали совпадающие
формулировки между Run 1 и Run 2. Qwen и Sakana — нет.

## Задача

Предложи единое определение шкалы YES / NO / AMBIGUOUS,
которое объединило бы лучшее из четырёх подходов.

Определение должно:
- устранять расхождение семантики, обнаруженное в 004;
- быть однозначным — два оператора, применяя его
  к одному ответу, приходят к одному результату;
- быть применимым вручную одним оператором;
- быть коротким.

Формат ответа:

    (а) итоговое определение YES / NO / AMBIGUOUS;
    (б) что из какого определения взято и почему;
    (в) что отброшено и почему;
    (г) какие противоречия между четырьмя определениями
        видишь и как разрешаешь;
    (д) где синтез может сломаться.

## Ограничения

- один оператор, ручная передача между чатами;
- без автоматизации.

## Условия

- Полные тексты четырёх определений из 005 передаются
  оператором по мере продвижения цикла.
- Ответ будет зафиксирован без редактуры.
- Язык — русский.

## Ограничение

Задача не меняется после старта эксперимента.
Любые правки — через новый эксперимент или через trace.md.
