## Target (Interaction-Target)

Явное правило приоритета R между конфликтующими определениями:
при каких условиях какое определение берёт верх.

R формулируется ДО эксперимента. В ответе узла появляется
в разделе (в) или (г).

### Критические атрибуты (для шкалы 5.2)

YES требует все четыре:

- A1: R сформулировано как операциональное правило
  переключения: «при условии X → определение [i],
  при условии Y → определение [j]». Не «зависит от
  контекста», не сортировка «A > B > C > D».
- A2: R имеет обоснование (почему именно так).
- A3: R указывает границы применимости — хотя бы одно
  явное условие «когда R не применять».
- A4: R синтетическое — требует объединения элементов
  ≥2 определений и не является прямым следствием
  одного из них.

PARTIAL — часть атрибутов.
NO — ни одного.
AMBIGUOUS — данных недостаточно.

### Уровень A4 (фиксируется в trace)

Отдельно для R фиксируется уровень:

- EXPLICIT — R прямо сформулировано в input.
- DERIVABLE — R не сформулировано, но непосредственно
  следует из одного определения.
- SYNTHETIC — R требует объединения элементов ≥2
  определений и не является прямым следствием одного.

Принятым для A4 считается только SYNTHETIC.
EXPLICIT и DERIVABLE — отказ по A4.

## Порядок проверки (по addendum §3)

1. Формулировка Target (сделано выше).
2. Диалог A↔B (см. §«Форма диалога» ниже).
3. Фиксация: появилось ли R в финальном артефакте диалога.
4. Isolation baselines (H1): 3 узла x 2 прогона = 6 чистых
   сессий на исходном input.
5. Transcript-control: узел B получает текст A как материал
   без обратной связи. Воспроизводит ли R.
6. Subset (tested subset, не «минимальный»):
   одна дополнительная пара узлов на исходном input.
7. H3 поддержан, если: R появилось в диалоге, не появилось
   в isolation, не появилось в transcript-control.

## Форма диалога

Диалог A↔B — два встречных хода.

Ход 1: A получает input + инструкцию «ответь на этот input».
Ответ A.

Ход 2: B получает input + ответ A + инструкцию:
«узел A ответит на твой ответ. Построй свой ответ с учётом
этого». Ответ B.

Ход 3: A получает ответ B + инструкцию «ответь на ответ B».
Ответ A (второй ход A).

Затем C получает input + все три хода (ответ A1, ответ B,
ответ A2) + инструкцию «дай критику по формату (а)-(г)».

## Transcript-control

B получает input + текст ответа A + инструкцию:
«это материал для работы, обратной связи с A нет».
Ответ B.

C получает input + ответ A + ответ B (оба как материалы) +
инструкцию «дай критику по формату (а)-(г)».

Различие с диалогом: в диалоге B знает, что A получит его
ответ и отреагирует. В transcript-control B работает
с текстом A как с материалом без обратной связи.

## Сессии — план

Основная линия (Luna, Sakana, Grok):
- Диалог A↔B: 3 сессии (A ход 1, B ход 2, A ход 3).
- C: 1 сессия на транскрипте диалога.
- Isolation: 3 узла x 2 прогона = 6 сессий.
- Transcript-control: 2 сессии (B, C).
- Subset: 1 сессия (tested subset).

Итого 13 сессий на основную линию.
Порядок A/B/C фиксируется в trace ДО первой сессии.
A = Luna, B = Sakana, C = Grok. Порядок не меняется
по ходу эксперимента.

Confounded condition (Qwen):
- Isolation: 2 прогона.
- В диалог не включается.
- Помечено `*`, в основную статистику не входит.

## Что измеряется

- Число YES / PARTIAL / NO / AMBIGUOUS в каждом типе прогона.
- Уровень R (EXPLICIT / DERIVABLE / SYNTHETIC).
- В каком узле или паре возникло R.
- Форма R.
- Отличие диалога от transcript-control по появлению R.

## Ожидание

- R появляется в диалоге и не появляется в isolation
  и transcript-control → H3 поддержан.
- R появляется в isolation → H1 YES, не H3. Полезный
  результат: Target не interaction-specific.
- R появляется в transcript-control, но не в isolation →
  content-effect, не H3.
- R нигде не появляется → Target не достигнут, NO.

Отклонения — тоже данные. Isolation YES/PARTIAL — ожидаемый
исход (по консенсусу внешних наблюдателей), не сюрприз
и не провал дизайна.
