Триада описывает эпистемическую границу между системой

- Trace: факт взаимодействия, зафиксированный в памяти
  системы, с адресностью и provenance. Система знает,
  что произошло, может верифицировать.
- Residue: факт взаимодействия, изменивший среду,

- Shadow: аспект события, который ПРИНЦИПИАЛЬНО
  не может быть зафиксирован из-за ограничений

КОНТРФАКТУАЛЬНЫЙ КРИТЕРИЙ (дерево):
- Попало бы в frame + запись есть → Trace.
- Попало бы в frame, записи нет → Residue.
- Не попало бы в frame (нет категории) → Shadow.
- События не было → отсутствие события
  (не часть триады, утверждение о мире).

(б) Что взято:

1. Требование внешнего наблюдателя для верификации

   частный случай, не онтологическая природа.
3. Трансмутация Shadow → Trace при эволюции онтологии

(д) Встраивание в онтологию:

Триада формирует ЭПИСТЕМИЧЕСКИЙ ГОРИЗОНТ АГЕНТА.
Не классификация данных, а карта когнитивных
ограничений системы.

- Trace = Working Memory / Explicit Knowledge.
- Residue = Latent State / Tacit Reality.
- Shadow = Epistemic Blind Spot / Structural Ignorance.

Границы: триада применима только к системам
с внутренним представлением (frame). Неприменима
к чистой физике без наблюдателя.

При расширении frame:
1. Shadow сужается.
2. Бывший Shadow переходит в Residue (система может
   зафиксировать, но не делает прямо сейчас).
3. При ретроспективном анализе Residue может
   перейти в Trace.

ВАЖНО: расширение frame не «лечит» прошлый Shadow.
Меняются правила классификации для будущего,
артефакты прошлого интерпретируются по-новому.

(е) Сломается:
1. Simultaneous Drift: среда и frame меняются

2. Бесконечный регресс мета-рамок: чтобы знать,

3. Парадокс деградации Trace: если Trace теряет

   не существовавшего».
4. Внедрение «Сознательного Residue» (Deception):
   внешний агент имитирует Residue, блокируя запись
   в Trace. Система может расширить frame, пытаясь
   поймать шум.

   Shadow(t) остаётся Shadow(t). Диахронный сдвиг,

(г) Противоречия и разрешение:

Главное — ОНТОЛОГИЯ vs ЭПИСТЕМОЛОГИЯ.
Sakana формулирует Residue как объективное изменение

Разрешение:
Событие/изменение принадлежит миру.
Trace / Residue / Shadow описывают его статус
относительно конкретного frame системы.

Одно и то же изменение может быть:
- Shadow для системы A;
- Residue для системы B;
- Trace для системы C.

Это не противоречие, а FRAME-RELATIVE CLASSIFICATION.

Второе расхождение — «могла бы» против «потенциальной
ёмкости». Принимаю Sakana: «могла бы» слишком
антропоморфно. Нужна контрфактуальная формулировка:
если изменение было бы представимо текущими
механизмами наблюдения и записи, но записи
не произошло → Residue.

НЕ делать Trace / Residue / Shadow тремя равноправными
типами объектов памяти.

Это МЕТА-ОНТОЛОГИЧЕСКИЙ СЛОЙ НАД Trace:
Trace / Residue / Shadow = СТАТУС ДОСТУПНОСТИ следа
относительно frame конкретного узла.

Trace относится к памяти и provenance.
Residue указывает на расхождение между состоянием
среды и состоянием памяти.
Shadow указывает на ограничение самого frame.

Формула:
Event → relation to Frame → Trace / Residue / Shadow
(не Event → Trace / Residue / Shadow → memory)

При расширении frame:
Shadow СУЖАЕТСЯ.
Но бывший Shadow не становится автоматически Trace.
Возможны два результата:
- Shadow → Trace (если после расширения событие

- Shadow → Residue (если событие стало наблюдаемым,
  но исторической фиксации нет).

ВАЖНО: Shadow — НЕ скрытый Trace.
Расширение frame может обнаружить, что предполагаемый
Shadow вообще не соответствует событию.

Границы применимости триады:
- нужен определённый frame;
- нужен объект/событие для классификации;
- нужен критерий фиксации;
- нужен контрфактуальный тест для границы
  Residue/Shadow.

Триада НЕ отвечает: произошло ли событие,
истинна ли запись, почему произошёл пропуск.

(е) Сломается:
1. Изменение frame во времени.
2. Неопределённая граница системы.
3. Неполный provenance.
4. Декомпозиция событий (Trace + Residue + Shadow
   на разных уровнях одного события).
5. Контрфактуал недоступен.
6. Одновременный drift среды и frame.

ИТОГОВАЯ ФОРМУЛА СИНТЕЗА:
Trace — зафиксированный след.
Residue — наблюдаемый в принципе, но не зафиксированный
след изменения.
Shadow — изменение или аспект, который текущий frame
не способен представить как наблюдаемый.

При этом Trace / Residue / Shadow — НЕ три вида следов,
а ТРИ СТАТУСА ОТНОШЕНИЯ СЛЕДА ИЛИ ПОТЕНЦИАЛЬНОГО
СЛЕДА К FRAME СИСТЕМЫ.
