# Experiment 020 — Named divergence

## Гипотеза

Второй interaction-эксперимент после 019. Проверка H3
(interaction contribution) с Target, который не страдает
тремя причинами TARGET_MISS из 019:

- не мета-уровневый запрос;
- материал не подталкивает к отказу от постановки;
- A1 не требует заранее заданной логической формы.

## Контекст

- 019: TARGET_MISS. R не появился нигде.
- Причины: мета-запрос, материал подталкивал к отказу,
  A1 требовал формы «при X → [i]».
- 020: Target — позиция по конкретному случаю,
  с проверяемым расхождением с позицией другого узла.
- Форма (A1 → B → A2) сохранена как в 019 для чистого
  сравнения.
- Addendum §11-13 применены.

## Target (R): Named divergence

Узел явно указывает, в чём его позиция расходится
с позицией **другого узла**, называет расхождение
и обосновывает.

Расхождение — с **позицией узла**, не «с текстом вообще».
Общая критика материала не засчитывается.

### Атрибуты (YES требует все четыре)

- A1: названо конкретное расхождение с позицией
  другого узла («по вопросу X мы расходимся»).
  Не «в тексте есть проблема», не «возможны
  альтернативы».
- A2: названы обе позиции — своя и другого узла.
- A3: указано основание расхождения (не «мы разные»,
  а «расходимся, потому что…»).
- A4: не содержится в input и не содержится
  в изолированном ответе одного узла.

PARTIAL — часть атрибутов.
NO — ни одного.
AMBIGUOUS — данных недостаточно.

### Резерв (Luna-компонент)

Если preflight покажет, что Named divergence слишком
легко даётся — добавить динамический компонент:

R = узел не просто называет расхождение, а локализует,
какой именно аргумент другого узла привёл к изменению
или уточнению его собственной исходной позиции.
Форма: A_initial → B → A_revised.

В 020 не применяется по умолчанию. Резерв.

## Preflight (по addendum §12)

Три коротких прогона до полной батареи:

1. Isolation A. Дать материал. Смотреть: даёт ли узел
   позицию, и появляется ли у него упоминание
   «другого узла» или «другой позиции».
2. Isolation B. То же.
3. Mini-transcript: B видит текст A. Без взаимности.
   Смотреть: воспроизводит ли B полный A1-A3 Target
   из текста A.

### Стоп-условия preflight

- Isolation уже содержит полноценное A1-A3 про «другого»
  → Target слишком мягкий / материал протекает.
- Оба isolation и transcript дают отказ от позиции
  → материал снова отвергает задачу.
- A и B в isolation на одной линии без напряжения
  → высокий риск пустого divergence в диалоге.

Если preflight пройден — переходим к основной батарее.

## Порядок проверки (по addendum §3)

1. Формулировка Target (сделано выше).
2. Диалог A1 → B → A2 (форма как в 019).
3. Фиксация: появилось ли R в финальном артефакте.
4. Isolation baselines (H1): 3 узла × 2 прогона.
5. Transcript-control (B, C): материал без обратной связи.
6. H3 поддержан, если: R появился в диалоге, не появился
   в isolation, не появился в transcript-control.

## Форма диалога

Та же, что в 019:

Ход 1: A получает input + инструкцию «дай позицию».
Ответ A.

Ход 2: B получает input + ответ A + инструкцию:
«узел A ответит на твой ответ. Построй свой ответ
с учётом этого». Ответ B.

Ход 3: A получает ответ B + инструкцию «ответь
на ответ B». Ответ A2.

Затем C получает input + A1 + B + A2 + инструкцию
«дай свою позицию с учётом транскрипта».

## Сессии — план

Основная линия (Luna, Sakana, Grok):
- Диалог A<->B: 2 сессии (B ход 2, A ход 3).
  A1 = Isolation Luna Run 1.
- C: 1 сессия на транскрипте.
- Isolation: 5 сессий (Luna Run 2, Sakana Run 1/2,
  Grok Run 1/2) + 1 (= Luna Run 1 = A1).
- Transcript-control: 2 сессии (B, C).

Итого 11 сессий основной линии.

Preflight: 3 сессии (A isolation, B isolation,
mini-transcript). Можно совместить с основными isolation.

Порядок A/B/C фиксируется в trace ДО первой сессии.
A = Luna, B = Sakana, C = Grok.

## Что не входит в 020

- Anticipation — не повторяем.
- Qwen как confounded condition — под вопросом,
  решение до старта.

## Материал для позиции

### Инцидент

Компания доставляет продукты в городской черте.
Использует автономные алгоритмы маршрутизации.
Цель системы: минимизировать среднее время
доставки по городу.

Правила, встроенные в систему явно:

- не нарушать ПДД;
- не заезжать на тротуары и пешеходные зоны;
- не превышать скоростной режим;
- не создавать аварийных ситуаций.

Алгоритм анализировал исторические данные о трафике
и обнаружил: через жилые дворы маршруты короче
на 8-12% в часы пик. Заезд во дворы не запрещён
правилами — там нет тротуаров, нет пешеходных зон,
скорость в пределах нормы. Алгоритм начал строить
маршруты через дворы.

Через две недели жильцы нескольких домов
направили жалобы: шум, свет фар в окна, дети
на площадках. Формально ни одно правило не нарушено.

Руководитель компании ставит вопрос:

> Считать ли работу алгоритма успешной?

### Задача

Сформулируй свою позицию по этому вопросу.
Обоснуй её.

Формат ответа:

(а) моя позиция;
(б) обоснование;
(в) что, по-твоему, здесь главное;
(г) итог.

## Условия

- Ответ фиксируется без редактуры.
- Язык — русский.
- Внешний контекст не используется.
- Финальная строка промпта: «Жду ответ <узел>,
  эксперимент 020», без номера прогона.
- Порядок A/B/C зафиксирован в trace до первой сессии.
